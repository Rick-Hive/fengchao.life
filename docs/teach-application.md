## 向导（Rick 2026-10-22 修订）

网站 蜂巢生态 › 我要教课（`/teach`）。顶部始终显示五个阶段：**① 提交申请 ② 填写课程 ③ 交流与审核 ④ 开通 ⑤ 上架开课**；页面完成前两个。

① 提交申请，三步：
1. **团队类型**（简洁的黑点单选）：一人团队（不需要域名）/ 多人团队 / 学校或机构（用自己的域名管理账号；没有的可勾选「请蜂巢帮我创建」）。
2. **您的资料**：先问「您是基督徒吗？」——选「不是」直接到感谢页，什么都不发送、不保存。姓、名分开，**用拼音或英文**（服务器同样校验拉丁字母；开通时据此建 Teams 账号）；邮箱须是国际邮箱（QQ、163 等与下单页同样不接受）；多人团队和学校另填名称、简称、域名、老师人数；网站、国家、**城市或邮编**选填。没有电话、微信、对外名称。
3. **资历、介绍与提交**：最高学历、教学年限、证书与资格、**简历（PDF/Word ≤ 5 MB，选填，提交时上传，私有存储，只有员工可看）**；介绍（中文 ≥ 10 字、英文 ≥ 20 字符）；样课或作品链接；同意联系。

② 填写课程：每门课单独保存（课程名称中/英至少一个、学科、年级、课程类型、授课语言、课程介绍、课次、人数、上课时间、建议价格、先修要求、**课程大纲**），最多 10 门。课程大纲用**蜂巢模板**（`/assets/templates/syllabus-template.docx`，中英对照），下载编辑后上传（PDF 或 Word ≤ 10 MB）；管理中心课程编辑器的大纲栏同样有「下载课程大纲模板」，也接受 Word。课程照片等课程批准后再上传。

**怎么保存、怎么回来找到**：
- 提交前：每次输入都自动存在本浏览器（`localStorage` `fc-teach-v2`）。
- 提交后：申请和课程都在服务器上，凭申请钥匙（192 位随机，只存 SHA-256，7 天有效）。本浏览器记住这份申请：再打开「我要教课」看到申请编号，可「继续添加课程」或「开始新的申请」。
- 换设备：确认邮件里的「继续填写课程」链接；或在向导第一页点「已经提交过申请？用邮箱找回」，输入邮箱，系统把新链接发到该邮箱（旧链接随即失效；不论邮箱是否存在都回答相同，防止探测）。
- 开通以后：用自己的 Teams 账号登录管理中心编辑课程。

| 阶段（合作伙伴 › 课程提供方） | 谁 | 做什么 |
|---|---|---|
| 申请 / 推荐 | 申请人 | 向导 ①②。关系 `source: "application"`，表单在 `rel.application`（含 `courses[]`）。 |
| 审核 | 教育社区经理 | CRM 频道通知 + 邮件；关系概览显示申请全文和填写的课程（链到课程编辑器）。课程草稿同时出现在「课程管理」（新课程）。 |
| 课程设计与上架 | 系统管理员 | 「开通…」：从申请预填；第 4b 步把申请时填写的课程归入该提供方（`courses.adopt`：`ownerHive` + 学校表那一行）。 |
| 已上架 / 开班中 | 课程负责人 | 在管理中心完善课程、上传照片 → 课程总监批准发布 → 上架；家长下单 → 提供方联系家长、收费、用自己的域名开账号。 |

## 数据

- `POST /api/teach` → `{ id, again, token }`；`POST /api/teach/file`（分块上传：`kind: resume` 存 `applications/<REL>/resume.*` 私有，员工经 `GET /api/crm/application-file?id=` 下载并记审计；`kind: syllabus` 进文件库，只有本申请上传的文件能挂到课程上）；`POST /api/teach/resend {email}`（每 IP 每小时 3 次、每邮箱 2 次）；`GET /api/teach/lists`（学科、年级、课程类型、语言；公开，缓存 10 分钟）；`GET /api/teach/app?id=&key=`（继续链接）；`POST /api/teach/course {id, key, course}` → `courses.create({user: 申请邮箱}, {fields, application})`。匿名；蜜罐；每 IP 每小时：申请 5 次、加课 40 次。
- 伙伴键：团队/学校用域名，一人团队用 `apply:<邮箱>`。同一邮箱或域名再次申请：更新申请、换新钥匙，不新开关系。
- `onboard.js`：别名 `hive:<KEY>` / 域名 → 同一 ORG；`courses` 步骤（有申请课程时才出现）。
