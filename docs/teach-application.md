## 向导（Rick 2026-10-22 修订）

网站 蜂巢生态 › 我要教课（`/teach`）。顶部始终显示五个阶段：**① 提交申请 ② 填写课程 ③ 交流与审核 ④ 开通 ⑤ 上架开课**；页面完成前两个。

① 提交申请，三步：
1. **团队类型**（简洁的黑点单选）：一人团队（不需要域名）/ 多人团队 / 学校或机构（都需要自己的域名来管理团队账号）。
2. **您的资料**：姓、名分开（提示「开通时将据此为您创建 Teams 账号」）、邮箱；多人团队和学校另填名称、简称（2–8 个字母或数字，用于订单频道）、域名（必填，不能是公共邮箱域名）、老师人数；网站、国家、城市选填。没有电话、微信、对外名称。一人团队不出现简称、域名。
3. **介绍与提交**：介绍（中文至少 10 个字、英文至少 20 个字符）、样课链接（选填）、同意联系。

② 填写课程：每门课单独保存（课程名称中/英至少一个、学科、年级、课程类型、授课语言、课程介绍、课次、人数、上课时间、建议价格、先修要求），最多 10 门；照片和大纲开通后在管理中心上传。学科、年级、授课语言都在这里按课填，不放在申请里。

**没登录怎么保存**：提交申请前，表单自动存在本浏览器（`localStorage` `fc-teach-v2`）；提交后服务器返回一把钥匙（随机 192 位，只存其 SHA-256；7 天有效），每门课凭它存到服务器。确认邮件带「继续填写课程」链接 `/teach?app=REL-…&key=…`，任何设备都能接着添课。

| 阶段（合作伙伴 › 课程提供方） | 谁 | 做什么 |
|---|---|---|
| 申请 / 推荐 | 申请人 | 向导 ①②。关系 `source: "application"`，表单在 `rel.application`（含 `courses[]`）。 |
| 审核 | 教育社区经理 | CRM 频道通知 + 邮件；关系概览显示申请全文和填写的课程（链到课程编辑器）。课程草稿同时出现在「课程管理」（新课程）。 |
| 课程设计与上架 | 系统管理员 | 「开通…」：从申请预填；第 4b 步把申请时填写的课程归入该提供方（`courses.adopt`：`ownerHive` + 学校表那一行）。 |
| 已上架 / 开班中 | 课程负责人 | 在管理中心完善课程、上传照片 → 课程总监批准发布 → 上架；家长下单 → 提供方联系家长、收费、用自己的域名开账号。 |

## 数据

- `POST /api/teach` → `{ id, again, token }`；`GET /api/teach/lists`（学科、年级、课程类型、语言；公开，缓存 10 分钟）；`GET /api/teach/app?id=&key=`（继续链接）；`POST /api/teach/course {id, key, course}` → `courses.create({user: 申请邮箱}, {fields, application})`。匿名；蜜罐；每 IP 每小时：申请 5 次、加课 40 次。
- 伙伴键：团队/学校用域名，一人团队用 `apply:<邮箱>`。同一邮箱或域名再次申请：更新申请、换新钥匙，不新开关系。
- `onboard.js`：别名 `hive:<KEY>` / 域名 → 同一 ORG；`courses` 步骤（有申请课程时才出现）。
