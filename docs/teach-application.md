# 我要教课 · 成为课程提供方（2026-10-22）

Rick 2026-10-22：「请按照你建议的流程设计“成为课程提供方”，网站上 menu 叫“我要教课”」。

## 流程

| 阶段（合作伙伴 › 课程提供方） | 谁 | 做什么 |
|---|---|---|
| 申请 / 推荐 | 申请人 | 网站 蜂巢生态 › 我要教课（`/teach`）填表：身份（个人老师 / 教学团队 / 学校或机构）、姓名、邮箱、电话或微信、名称、简称、网站、自己的邮箱域名、国家城市、想开的课程、年级、授课语言、老师人数、介绍、样课链接、同意联系。登录时记下账号（平台给的，不取自表单）。 |
| 审核 | 教育社区经理 | 收到 CRM 频道通知（订单经理 / `CRM_DIGEST_TO` 兜底）和管理中心里的申请；联系、了解课程与教学，手动推进阶段。 |
| 课程设计与上架 | 系统管理员 | 关系概览「开通…」：没有机构行时直接用申请里的名称、简称、域名、邮箱、地区；负责人填申请人的蜂巢账号（没有就先新建或先空着，之后再执行一次）。开通把 `hive:<简称>`（和域名）挂到同一个 ORG，学校表那一行与申请是同一个伙伴。 |
| 已上架 / 开班中 | 课程负责人 | 管理中心建课 → 课程总监批准发布 → 网站上架；家长下单 → 提供方联系家长、收课程费 → 用自己的域名为学生开账号。 |

## 数据

- `POST /api/teach`（匿名；蜜罐、每实例每 IP 每小时 5 次）→ `api/shared/applications.js`：
  - 伙伴键：自己的域名（公共邮箱域名不算），否则 `apply:<邮箱>`；ORG 由 `orgIdFor` 生成。
  - 新建 `course` 关系，阶段 `apply`，`source: "application"`，表单存于 `rel.application`（含 `at`、`firstAt`、`account`）。
  - 同一邮箱或同一域名已有未关闭的课程提供方关系 → 不再新建：更新 `application`，跟进记一条「再次提交」。
  - 通知：同一个 Power Automate 流——邮件给申请人（按申请语言的确认信），一条 route 到 CRM 频道、`notifyEmail` = 教育社区经理（`staff:community`），没有时用摘要收件人。失败不影响记录。
- 管理中心：关系卡片带「网站申请」标签；概览显示申请全文；「开通」从申请预填（`ptOnboardStatus` 找不到机构行时用申请构造）。
- `onboard.js` 第 3 步：别名 `hive:<KEY>` / 域名 → 同一 ORG（只补空缺，不改已有映射）。
