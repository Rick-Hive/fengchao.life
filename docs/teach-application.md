## 向导（Rick 2026-10-22 修订）

网站 蜂巢生态 › 我要教课（`/teach`）。顶部始终显示五个阶段：**① 提交申请 ② 填写课程 ③ 交流与审核 ④ 开通 ⑤ 上架开课**；页面完成前两个。

① 提交申请，三步（卡片顶部是可点击的分步条 ① 教学团队 › ② 基本信息 › ③ 教学资质，恢复上次填写时一眼可见在哪一步）：
1. **教学团队**（黑点单选）：一人团队（不需要域名）/ 多人团队 / 学校或机构（用自己的域名管理账号；没有的可勾选「请蜂巢帮我创建」）。页脚「已经提交过申请？用邮箱找回」。
2. **基本信息**：姓（拼音）、名（拼音或英文名）（服务器同样校验拉丁字母；开通时据此建 Teams 账号）；邮箱须是国际邮箱（QQ、163 等与下单页同样不接受）；多人团队和学校另填名称、简称、域名、老师人数；国家、**城市或邮编**、**个人主页或机构网站**选填。登录状态只在分步条右侧小字显示，不占一行。
3. **教学资质**：**个人简历（必填，PDF/Word ≤ 5 MB）**、**示范课与作品集链接（必填）**；信仰分级提问，每个回答打开下一问，任何回答都进入下一步、不拒绝（Rick 2026-10-23）：「您听说过基于圣经的世界观吗？」是/否 → 是：「您在教学中融入圣经世界观的频率？」从未/偶尔/经常/每堂课都有 → 非从未：「您有委身的教会生活吗？」→ 是：「我委身的教会」家庭教会/三自教会/网络教会/其它（说明）。页面注明这些答案只有教育社区经理可见；提交后本浏览器不再保留这些答案。同意条款含「为审核保存以上信息」。不再有学历、年限、证书、自我介绍栏目（简历里都有）。

② 添加课程：已保存课程列表 + 「＋ 添加课程」按钮，点开表单（取消/保存课程）。控件照管理中心课程编辑器：学科 chips + 「添加学科…」下拉（含「其它学科（请说明）」→ 写入备注给课程总监）、**年级 checkbox 多选、按站点语言显示**（学前 / 幼儿园 K1 / 1 年级… · Pre-K / K1 / Grade 1…）、课程类型与授课语言 pills、课时数/人数、**上课时间 = 星期 pills + 起止时间 → 「添加时段」**（结构化保存，按语言显示，课程的上课星期 = 各时段并集），先修要求、建议价格、课程大纲（选填，开通后也可补）：「下载模板」→ 填好 → 上传（PDF/Word ≤ 10 MB）。最多 10 门。没有课程照片提示。分步条右侧显示申请编号和当前阶段（「当前：等待蜂巢联系 / 审核中 / 已开通…」）。「编辑申请」回到三步修改（凭钥匙保存，简历、课程、钥匙不变，邮箱不可改）。简历未上传成功时这里补传。

**课程大纲模板**：管理中心 › 课程管理 › 「大纲模板…」（课程总监/CEO/系统管理员）上传 .docx（≤ 4 MB）替换蜂巢内置模板；网站和课程编辑器都从 `/api/asset?key=templates/syllabus-template.docx` 下载（未上传时 302 到内置的 `/assets/templates/syllabus-template.docx`）。

**怎么保存、怎么回来找到**：
- 提交前：每次输入都自动存在本浏览器（`localStorage` `fc-teach-v3`，恢复时校验形状）。
- 提交后：申请和课程都在服务器上，凭申请钥匙（192 位随机，只存 SHA-256，7 天有效）。本浏览器记住这份申请：再打开「我要教课」看到申请编号，可「继续添加课程」「编辑申请」或「开始新的申请」。
- 换设备：确认邮件里的链接 `/teach#app=REL-…&key=…`（钥匙在 URL 片段里，不进服务器日志，页面用 POST 换取）；或在第一页「用邮箱找回」，系统把新链接发到该邮箱。换新钥匙后旧钥匙再保留 1 小时（正在填写的标签页不被打断）；不论邮箱是否存在页面回答相同，防止探测。
- 钥匙失效（过期、已换新）时页面说明并直接给出「用邮箱找回」。
- 开通以后：用自己的 Teams 账号登录管理中心编辑课程。

**安全（2026-10-24 复审后）**：用已有邮箱/域名再次提交**不改动**已有申请、**不返回钥匙**（防止知道邮箱的人接管申请、覆盖简历、塞课程）；是本人的话会收到一封新链接邮件；域名已是提供方的，什么都不发。上传按实际字节计数（不信客户端声明的大小）、块数有上界、同一上传只接受同一发起者的块；简历块索引有界、类型记在申请上；申请上传的大纲文件打上申请标签，被课程引用时「认领」，7 天无人认领或 1 天未完成的由夜间作业第 7 步清除。限流按最旧桶淘汰，不整体清空；IP 去掉端口。信仰答案在管理中心只对教育社区经理 / CEO / 系统管理员显示。

|---|---|---|
| 申请 / 推荐 | 申请人 | 向导 ①②。关系 `source: "application"`，表单在 `rel.application`（含 `courses[]`）。 |

| 已上架 / 开班中 | 课程负责人 | 在管理中心完善课程、上传照片 → 课程总监批准发布 → 上架；家长下单 → 提供方联系家长、收费、用自己的域名开账号。 |

## 数据

- `POST /api/teach` → `{ id, again:false, token }`（重复申请 → `{ again:true }` 无钥匙）；`POST /api/teach/app {id,key}`（继续链接）；`POST /api/teach/update {id,key,form}`（编辑申请）；`POST /api/teach/file`（分块上传：`kind: resume` 存 `applications/<REL>/resume.*` 私有，员工经 `GET /api/crm/application-file?id=` 下载并记审计；`kind: syllabus` 进文件库，只有本申请上传的文件能挂到课程上）；`POST /api/teach/resend {email}`（每 IP 每小时 3 次、每邮箱 2 次）；`GET /api/teach/lists`（学科、年级、课程类型、语言；公开，缓存 10 分钟）；`GET /api/teach/app?id=&key=`（继续链接）；`POST /api/teach/course {id, key, course}` → `courses.create({user: 申请邮箱}, {fields, application})`。匿名；蜜罐；每 IP 每小时：申请 5 次、加课 40 次。
- 伙伴键：团队/学校用域名，一人团队用 `apply:<邮箱>`。同一邮箱或域名再次申请：更新申请、换新钥匙，不新开关系。
- `onboard.js`：别名 `hive:<KEY>` / 域名 → 同一 ORG；`courses` 步骤（有申请课程时才出现）。
