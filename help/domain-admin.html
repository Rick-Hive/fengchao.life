蜂巢管理中心

域管理员操作手册

给学校的 IT 管理员：在蜂巢管理中心里，你能对本校账号做什么、怎么做、要注意什么。这里的每一步操作都通过蜂巢作用在 Microsoft 365 上——你改的，就是 Teams 和 Outlook 看到的。

1　角色：谁是域管理员

蜂巢里有四类人。你的角色决定你看到哪些页面、哪些按钮可用。

角色是谁可以做
普通用户每一位有学校账号的老师、家长、学生自己的资料、登录与安全、自己的 Teams
域管理员（IT）学校的 IT 负责人，由蜂巢的系统管理员在「角色分配」里指定。不需要（也不建议）在 Microsoft 365 里持有任何管理员角色：账号在那边仍是普通账号。本手册里的一切：查看本校账号、新建和删除账号、删除验证设备、重置密码、同步变动
域蜂巢管理员学校里负责蜂巢事务的人（非 IT）查看本校账号；填身份、关联账号、备注；不能动设备和密码
系统管理员蜂巢的系统管理员所有学校的一切

你的角色显示在管理中心左下角你的名字下方，以及「个人资料」的第一行。如果显示「普通用户」，请联系蜂巢的系统管理员为你分配角色；分配后立即生效，无需重新登录。

2　登录、切换账号、退出

登录

打开 fengchao.life，点右上角「登录」。微软会显示账号列表——选你的学校账号（或点「使用其他账户」输入），在验证器上批准，管理中心随即打开。同一个浏览器里同一时间只能登录一个账号。

切换账号

点左下角你的名字 →「使用新账号登录」（如果你在补充资料里登记了其它账号，则叫「切换账号」，并列出它们）。蜂巢先结束当前会话，微软会问「退出哪个账号」，然后显示账号列表供你用新账号登录。

退出与超时

左下角的「退出」结束蜂巢会话以及本站在微软那里的登录 cookie。30 分钟无操作，或登录满 12 小时，会自动退出（最后一分钟有倒计时提示）。在公用电脑上，离开前务必点「退出」并关闭浏览器。

3　「用户」页与数据来源

左侧菜单 →「本域管理」→「用户」。你只会看到自己管理的学校。表格列出本校所有账号：账号、显示名与最近登录、是否登记了验证器（验证 Yes/No）、设备、Teams 群组、身份、关联账号。

数据从哪里来

页面读的是蜂巢里的一份缓存，不是实时去问微软——所以即使学校很大也能秒开。缓存每天北京时间 01:00 自动刷新；表格下方一行字写着上次同步时间。

「同步变动」——什么时候点

当学校的 Microsoft 365 里今天有了变动、你现在就要看到——新入职老师的账号、改了名的账号、被删掉的账号。它只读取上次同步之后新增、修改、删除的部分，而且只针对你的学校，通常几秒钟完成。「完整同步」（重读所有人）留给系统管理员和夜间任务。

筛选、搜索、导出

表格上方的筛选：全部 / 未登记验证器（这些账号还过不了登录验证——开学时重点跟进）/ 身份未填 / 从未登录。学校旁边的角色下拉框按身份（家长、学生、老师、行政、教育顾问）、按蜂巢角色（域管理员、域蜂巢管理员、Staff、系统管理员）筛选，或只看蜂巢课程教师——身份为老师的所有人，加上课程目录教师表里的人（按 Teams 账号匹配）。管理多所学校的人可以在学校下拉框里选「所有学校」跨校筛选。搜索框匹配账号、姓名、群组、角色。「导出 CSV」把当前看到的表格下载下来。

4　人员面板

点任意一行，右侧打开这个人的面板。你能对一个账号做的事都在这里。

基本信息

账号、学校、身份、角色、安全邮箱、城市、孩子、是否已验证、最近登录、创建日期、账号是否启用。来自 Microsoft 365 以及本人自己填写的内容。

验证设备

能批准这个人登录的每一台设备，含型号、验证器版本、添加日期。「删除」移除一台；对方下次登录时微软会要求重新注册设备。允许删除唯一的设备（手机丢了），但请在对方新手机已经准备好时再删，否则在此之前他登不进去。

密码——重置

点「重置」→ 确认 → 蜂巢为该账号设置一个 14 位临时密码，并只显示一次，带「复制」按钮。对方的旧密码立即失效；临时密码在对方用它登录并设置新密码之前一直有效（首次登录时微软会强制改密）。请通过电话或当面告知——不要发到群里，也不要发到他正好打不开的那个邮箱。关闭面板后不再显示，蜂巢不保存副本。

删除账号

对本校的普通账号（没有蜂巢角色的账号）：「删除」→ 输入该账号确认。微软把账号、邮箱和 OneDrive 移入回收站，30 天内蜂巢的系统管理员可在 Microsoft 365 管理中心恢复，之后永久删除。带蜂巢角色的账号要先在「角色分配」里移除角色才能删。

身份 / 关联账号 / 备注

见第 7 节。

Teams 群组

这个人所在的群组和团队；点一个，打开该群组的面板，列出本校成员。

5　常见情况的处理步骤

5.1「我换了手机，验证提示还发到旧手机上。」
  1. 如果旧手机还能用，让本人在旧手机上批准一次，然后自己到 mysignins.microsoft.com/security-info 添加新手机。你无需操作。
  2. 旧手机不在了：打开人员面板 →「验证设备」→「删除」旧设备。
  3. 让本人登录 Teams：微软会提示「需要更多信息」，引导注册新手机。可把设置向导发给他。

结果：下次登录时注册新手机；旧手机再也批准不了任何登录。

5.2「我忘记密码了。」
  1. 先确认提出请求的确实是账号本人——用已知号码回拨，或当面处理。重置密码是这里最敏感的操作。
  2. 人员面板 →「密码」→「重置」→ 确认。把临时密码念给对方，或让他从你屏幕上抄。
  3. 对方用临时密码登录；微软立刻要求设置新密码，然后照常要求验证器批准。

结果：本人设好新密码，临时密码作废。这次重置带着你的名字记入审计日志。

5.3「手机丢了，密码也忘了。」
  1. 当面核实身份——这正是冒充者会说的组合。
  2. 人员面板 →「验证设备」→「删除」丢失的手机（即使它是唯一设备）。
  3. 同一面板 →「密码」→「重置」，交付临时密码。
  4. 对方在新手机上登录：先设新密码，再按「需要更多信息」注册验证器。
5.4新老师或新家庭加入：创建账号。
  1. 「用户」页 → 右上角「＋ 新建账号」。填姓、名（显示名自动生成：李明，或 Ann Lee）、账号名（字母、数字和 . _ -，通常用拼音 名.姓），以及三个必填项：身份（学生 / 家长 / 老师 / 行政）、所在城市、邮编。职务可选。
  2. 许可证：两个选项——Office 365 A1 for students（仅限学生）或 Office 365 A1 for faculty（老师、家长、行政）。选了身份会自动选对应方案，表单不允许学生用 faculty、也不允许非学生用 students。每个新账号同时获得 Microsoft Power Automate Free。列表里显示每种还剩多少席位；没有许可证的账号用不了 Teams 和 Outlook。
  3. 「创建账号」→ 账号和临时密码只显示一次。电话或当面告知对方，并附上设置向导：首次登录微软会要求设新密码，然后引导注册验证器。

结果：账号已在学校的 Microsoft 365 里建好（部门字段填的是学校名，城市和邮编也已写入），立刻出现在「用户」表里（注册验证器前「验证」为 No），对方一登录就能用 Teams。

5.5开学了：谁还登不进去？

「用户」页 → 筛选「未登记验证器」。列出的人都有账号但还没有验证器，第一次登录 Teams 会停在「需要更多信息」。提前把设置向导发给他们；需要和同事分工的话用「导出 CSV」导出名单。

5.6一个账号上显示两台验证设备。

多半是本人加了新手机、没删旧的——无害。问一下本人；如果两台都是他的，保留或删掉不再用的那台。如果本人不认识其中一台，当天删掉并重置密码，然后告知系统管理员。参见案例 6.1。

6　Teams 群组

左侧菜单 →「本域管理」→「Teams 群组」：所有含本校成员的团队和群组，标明类型（班级团队 = 用教育版班级模板创建的团队；普通团队；群组 = 没有 Teams 的 Microsoft 365 / 邮件 / 安全组）、可见性、本校成员数。「查看成员」列出成员，点成员可打开其面板。

本页是只读的：增删成员仍在 Teams 或 Microsoft 365 管理中心里做。那里改的成员关系在夜间同步（或系统管理员的「完整同步」）之后显示。

7　身份、关联账号与补充资料

人员面板底部：身份（家长 / 学生 / 老师 / 行政——蜂巢自己的标签，与微软无关；为空时回退到 Microsoft 365 里的部门字段）、关联账号（孩子或家长的账号，逗号分隔，双方互相关联）、以及不超过 200 字的备注。「保存」只写入蜂巢。

「补充资料（本人填写）」显示本人在自己的「个人资料」页填写的内容——身份/角色、感兴趣的话题、其它账号、孩子的年龄与年级。对你是只读的，需要改请让本人自己改。家长在那里填了孩子的账号，会自动与孩子关联。

8　安全、审计与权限边界

几条原则

  • 先核实，再操作。凭陌生来电就删设备、重置密码，等于把账号交给对方。用已知号码回拨，或当面处理。
  • 每一步都有记录——谁、何时、对哪个账号、哪台设备、结果——同时记在蜂巢和微软的审计日志里。没有无痕操作。
  • 临时密码口头传递。不要贴进群聊、工单或邮件。
  • 公用电脑上务必退出并关闭浏览器。自动超时是兜底，不是习惯。
  • 你自己的账号：条件允许就保留两台验证设备；改密码走「登录与安全」→「修改密码」。

域管理员做不了的事

  • 改名、停用账号——由学校在 Microsoft 365 里做（创建和删除账号在这里做，见第 4 节和 5.4）。
  • 修改群组或团队成员（这里只读）。
  • 动一个本身是 Microsoft 365 管理员的账号：对这类账号，微软拒绝任何人通过蜂巢删设备或重置密码。
  • 查看或更改其他学校。
  • 分配蜂巢角色（系统管理员 →「角色分配」）。

9　用登录日志和审计日志定位登录问题（配合 AI）

「登不进去」背后有十来种原因——密码错了、验证器在一部已经不在的手机上、验证请求超时没批准、试太多次被锁定、误用了个人微软账号……微软把每一次尝试都记了下来。两份可下载的日志，加上一个 AI 助手，能把猜来猜去变成五分钟的诊断。本节写给域管理员；末尾的方框写给登不进去的本人。

两份日志是什么、从哪里拿

日志记录什么谁能下载、在哪里
登录日志最近 7 天的每一次登录尝试：时间、哪个应用（Teams、Outlook、蜂巢网站……）、成功还是失败、失败原因和微软的错误码、IP 地址与地点、操作系统与浏览器。账号本人：管理中心 →我的账号 → 登录与安全→「登录日志」→「下载」（CSV 或 JSON）。蜂巢的系统管理员在 Microsoft Entra 里能看到同样的记录（30 天）。
审计日志最近 7 天对账号本身的每一次更改：重置或修改密码、添加或删除验证器、修改资料、加入群组——含操作者（本人、管理员，还是蜂巢系统）和结果。不记录聊天和文件。同一处，「审计日志」→「下载」。你在管理中心做的操作（删设备、重置密码）会以你的名字出现在这里。
你自己能直接看到的人员面板（第 4 节）里：最近登录、验证 Yes/No、每台验证设备的型号、版本和添加日期、账号是否启用。你——不用下载。先看这里：一半的情况光看设备列表就能定。

只有本人能下载自己的日志，域管理员拉不到别人的——这是有意为之：日志里写着一个人在哪里、用什么设备。所以第一步永远是请本人导出并发给你。

9.1处理步骤：从「登不进去」到找到原因
  1. 先看人员面板（「用户」→ 此人）。最近登录很久以前、验证 No → 本人从没完成验证器注册（案例 2.1）。设备型号和他现在手里的手机对不上 → 换过手机（5.1）。账号已停用 → 学校在 Microsoft 365 里关掉了。面板能定的，到此为止。
  2. 请本人导出两份日志发给你——Teams 私聊或发到你个人邮箱，不要发到群里。如果他连管理中心都打不开（这正是问题所在），可以在任何一台还保持登录的浏览器上操作，或借同事的电脑用无痕窗口登录一次；实在不行，带着报错截图直接跳到第 5 步。
  3. 自己先读登录日志——用 Excel 打开 CSV，按时间排序，看 ok、code、reason 三列。9.2 的表翻译了常见错误码。连续多行同一个码才是线索；孤零零的一行多半是噪音。
  4. 把两个文件交给 AI 助手，用 9.3 的提示词，要它给出时间线和最可能的原因。只用 Claude、ChatGPT（OpenAI）或 Gemini——原因和上传前要删什么，见 9.3 的安全提示。
  5. 按结论操作，对照 9.4 的表找到本手册里对应的步骤。删设备、重置密码之前照例先核实身份（第 8 节）。
  6. 处理完删掉日志文件——你的下载目录、聊天记录、AI 对话（删除该对话）里都删。那是你帮助的那个人的个人数据。

结果：说得出的原因、第 5 节里的对应处理、给本人的一句话说明——通常十分钟内，不用再让他「再试一次」。

9.2读懂登录日志：字段和常见错误码

字段

time（UTC，北京时间加 8 小时）· app 哪个应用 · client 浏览器还是手机 App · ok 成功与否 · code 微软错误码（0 = 成功）· reason、detail 微软的说明 · ip、place 从哪里发起 · os、browser 什么设备 · ca 是否触发了访问策略。

审计日志有 time、activity（发生了什么）、result、reason、by（谁做的）、targets（对谁）。常见的 activity：User registered security info（添加了验证器）、User deleted security info（删除了验证器）、Reset user password（管理员重置密码）、Change user password（本人改密码）、Update user（资料更新）。

9.3让 AI 读日志——安全地

安全第一：用哪个 AI，不上传什么

  • 只用 Claude（claude.ai）、ChatGPT（OpenAI）或 Gemini（Google）。这些日志不要贴进或上传到任何在中国大陆运营的 AI 服务——DeepSeek、豆包、Kimi、通义千问、文心一言、智谱等——也不要给来路不明的「免费」工具或浏览器插件。日志里有我们的老师、家长、学生在哪里、用什么设备、账号叫什么；这些信息不能落到那些管辖范围内，也不能进任何人的训练数据。
  • 在 AI 的设置里关掉「用我的对话改进模型」（三家都有这个开关），或者使用默认关闭的付费 / 工作版。处理完删除对话。
  • 删掉诊断用不着的列。先打开 CSV，删去 ip 列；诊断有 place 列就够了。绝不包含临时密码、临时密码的截图或群聊内容。
  • 一个对话只放一个人的日志。不要把几个人的文件堆进同一个对话。

提示词——复制、填好方括号、附上两个文件

你在帮助一所学校的 IT 管理员诊断一个 Microsoft 365 登录问题。附件是一位用户的登录日志和审计日志（CSV，最近 7 天，时间为 UTC，请换算成北京时间 UTC+8）。用户的描述：[本人的原话，例如「Teams 让我在手机上批准，但手机上什么都没收到」——大约从 [日期] 开始]。他现在用的手机是 [型号]；管理员在账号上看到这些验证设备：[从人员面板抄下来的列表，含添加日期]。

请：
1. 按日期、应用、设备整理一条时间线，标出成功与失败。
2. 把出现过的每个错误码（AADSTS…）翻译成通俗的话。
3. 把审计日志对到时间线上：改密码、增删验证器，各是谁做的。
4. 给出最可能的单一原因、支持它的证据，以及一两个备选解释。
5. 指出可疑之处：从陌生地点或设备的成功登录、不是本人登记的设备、短时间内大量密码错误。
6. 用一两句话建议下一步，从这些里选：删除某台验证设备；重置密码；请用户注册验证器（「需要更多信息」）；账号被停用或被策略阻止——转交系统管理员；改用学校账号而不是个人账号登录；无需修复——说明用户该怎么做。
请用中文简要回答，不要复述原始日志。

批判地读它的回答：AI 看到的是日志，不是人。如果它的结论和你在人员面板里看到的相矛盾（它说没有的设备其实列在那里），以面板为准。拿不准时，把它的摘要——不带文件——发给系统管理员。

给登不进去的本人：自己先走一遍

  • 下载你的两份日志：管理中心 →我的账号 → 登录与安全→「登录日志」→「下载」，再「审计日志」→「下载」（CSV）。任何一台你还保持登录的浏览器都可以。
