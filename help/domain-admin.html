蜂巢管理中心

域管理员操作手册

给学校的 IT 管理员：在蜂巢管理中心里，你能对本校账号做什么、怎么做、要注意什么。这里的每一步操作都通过蜂巢作用在 Microsoft 365 上——你改的，就是 Teams 和 Outlook 看到的。

1　角色：谁是域管理员

蜂巢里有四类人。你的角色决定你看到哪些页面、哪些按钮可用。

角色是谁可以做
普通用户每一位有学校账号的老师、家长、学生自己的资料、登录与安全、自己的 Teams
域管理员（IT）学校的 IT 负责人，由蜂巢的系统管理员在「角色分配」里指定。不需要（也不建议）在 Microsoft 365 里持有任何管理员角色：账号在那边仍是普通账号。本手册里的一切：查看本校账号、删除验证设备、重置密码、同步变动
域蜂巢管理员学校里负责蜂巢事务的人（非 IT）查看本校账号；填身份、关联账号、备注；不能动设备和密码
系统管理员蜂巢的系统管理员所有学校的一切

你的角色显示在管理中心左下角你的名字下方，以及「个人资料」的第一行。如果显示「普通用户」，请联系蜂巢的系统管理员为你分配角色；分配后立即生效，无需重新登录。

2　登录、切换账号、退出

登录

打开 fengchao.life，点右上角「登录」。微软会显示账号列表——选你的学校账号（或点「使用其他账户」输入），在验证器上批准，管理中心随即打开。同一个浏览器里同一时间只能登录一个账号。

切换账号

点左下角你的名字 →「使用新账号登录」（如果你在补充资料里登记了其它账号，则叫「切换账号」，并列出它们）。蜂巢先结束当前会话，微软会问「退出哪个账号」，然后显示账号列表供你用新账号登录。

退出与超时

左下角的「退出」结束蜂巢会话以及本站在微软那里的登录 cookie。30 分钟无操作，或登录满 12 小时，会自动退出（最后一分钟有倒计时提示）。在公用电脑上，离开前务必点「退出」并关闭浏览器。

3　「用户」页与数据来源

左侧菜单 →「本域管理」→「用户」。你只会看到自己管理的学校。表格列出本校所有账号：账号、显示名与最近登录、是否登记了验证器（验证 Yes/No）、设备、Teams 群组、身份、关联账号。

数据从哪里来

页面读的是蜂巢里的一份缓存，不是实时去问微软——所以即使学校很大也能秒开。缓存每天北京时间 01:00 自动刷新；表格下方一行字写着上次同步时间。

「同步变动」——什么时候点

当学校的 Microsoft 365 里今天有了变动、你现在就要看到——新入职老师的账号、改了名的账号、被删掉的账号。它只读取上次同步之后新增、修改、删除的部分，而且只针对你的学校，通常几秒钟完成。「完整同步」（重读所有人）留给系统管理员和夜间任务。

筛选、搜索、导出

表格上方的筛选：全部 / 未登记验证器（这些账号还过不了登录验证——开学时重点跟进）/ 身份未填。搜索框匹配账号、姓名、群组。「导出 CSV」把当前看到的表格下载下来。

4　人员面板

点任意一行，右侧打开这个人的面板。你能对一个账号做的事都在这里。

基本信息

账号、学校、身份、角色、安全邮箱、城市、孩子、是否已验证、最近登录、创建日期、账号是否启用。来自 Microsoft 365 以及本人自己填写的内容。

验证设备

能批准这个人登录的每一台设备，含型号、验证器版本、添加日期。「删除」移除一台；对方下次登录时微软会要求重新注册设备。允许删除唯一的设备（手机丢了），但请在对方新手机已经准备好时再删，否则在此之前他登不进去。

密码——重置

点「重置」→ 确认 → 蜂巢为该账号设置一个 14 位临时密码，并只显示一次，带「复制」按钮。对方的旧密码立即失效；临时密码在对方用它登录并设置新密码之前一直有效（首次登录时微软会强制改密）。请通过电话或当面告知——不要发到群里，也不要发到他正好打不开的那个邮箱。关闭面板后不再显示，蜂巢不保存副本。

身份 / 关联账号 / 备注

见第 7 节。

Teams 群组

这个人所在的群组和团队；点一个，打开该群组的面板，列出本校成员。

5　常见情况的处理步骤

5.1「我换了手机，验证提示还发到旧手机上。」
  1. 如果旧手机还能用，让本人在旧手机上批准一次，然后自己到 mysignins.microsoft.com/security-info 添加新手机。你无需操作。
  2. 旧手机不在了：打开人员面板 →「验证设备」→「删除」旧设备。
  3. 让本人登录 Teams：微软会提示「需要更多信息」，引导注册新手机。可把设置向导发给他。

结果：下次登录时注册新手机；旧手机再也批准不了任何登录。

5.2「我忘记密码了。」
  1. 先确认提出请求的确实是账号本人——用已知号码回拨，或当面处理。重置密码是这里最敏感的操作。
  2. 人员面板 →「密码」→「重置」→ 确认。把临时密码念给对方，或让他从你屏幕上抄。
  3. 对方用临时密码登录；微软立刻要求设置新密码，然后照常要求验证器批准。

结果：本人设好新密码，临时密码作废。这次重置带着你的名字记入审计日志。

5.3「手机丢了，密码也忘了。」
  1. 当面核实身份——这正是冒充者会说的组合。
  2. 人员面板 →「验证设备」→「删除」丢失的手机（即使它是唯一设备）。
  3. 同一面板 →「密码」→「重置」，交付临时密码。
  4. 对方在新手机上登录：先设新密码，再按「需要更多信息」注册验证器。
5.4新老师入职，列表里没有这个账号。

蜂巢不创建账号——账号仍由学校在 Microsoft 365 里按原来的方式创建。账号建好后，在「用户」页点「同步变动」，几秒钟后这一行出现，在老师注册验证器之前「验证」为 No。可顺手在人员面板里把身份设为「老师」。

5.5开学了：谁还登不进去？

「用户」页 → 筛选「未登记验证器」。列出的人都有账号但还没有验证器，第一次登录 Teams 会停在「需要更多信息」。提前把设置向导发给他们；需要和同事分工的话用「导出 CSV」导出名单。

5.6一个账号上显示两台验证设备。

多半是本人加了新手机、没删旧的——无害。问一下本人；如果两台都是他的，保留或删掉不再用的那台。如果本人不认识其中一台，当天删掉并重置密码，然后告知系统管理员。参见案例 6.1。

6　Teams 群组

左侧菜单 →「本域管理」→「Teams 群组」：所有含本校成员的团队和群组，标明类型（班级团队 = 用教育版班级模板创建的团队；普通团队；群组 = 没有 Teams 的 Microsoft 365 / 邮件 / 安全组）、可见性、本校成员数。「查看成员」列出成员，点成员可打开其面板。

本页是只读的：增删成员仍在 Teams 或 Microsoft 365 管理中心里做。那里改的成员关系在夜间同步（或系统管理员的「完整同步」）之后显示。

7　身份、关联账号与补充资料

人员面板底部：身份（家长 / 学生 / 老师 / 行政——蜂巢自己的标签，与微软无关；为空时回退到 Microsoft 365 里的部门字段）、关联账号（孩子或家长的账号，逗号分隔，双方互相关联）、以及不超过 200 字的备注。「保存」只写入蜂巢。

「补充资料（本人填写）」显示本人在自己的「个人资料」页填写的内容——身份/角色、感兴趣的话题、其它账号、孩子的年龄与年级。对你是只读的，需要改请让本人自己改。家长在那里填了孩子的账号，会自动与孩子关联。

8　安全、审计与权限边界

几条原则

  • 先核实，再操作。凭陌生来电就删设备、重置密码，等于把账号交给对方。用已知号码回拨，或当面处理。
  • 每一步都有记录——谁、何时、对哪个账号、哪台设备、结果——同时记在蜂巢和微软的审计日志里。没有无痕操作。
  • 临时密码口头传递。不要贴进群聊、工单或邮件。
  • 公用电脑上务必退出并关闭浏览器。自动超时是兜底，不是习惯。
  • 你自己的账号：条件允许就保留两台验证设备；改密码走「登录与安全」→「修改密码」。

域管理员做不了的事

  • 创建、改名、停用、删除账号——由学校在 Microsoft 365 里做。
  • 修改群组或团队成员（这里只读）。
  • 动一个本身是 Microsoft 365 管理员的账号：对这类账号，微软拒绝任何人通过蜂巢删设备或重置密码。
  • 查看或更改其他学校。
  • 分配蜂巢角色（系统管理员 →「角色分配」）。

9　获取帮助

给你支持的人：设置向导、问答和案例分析能回答大多数验证器问题，可以直接转发。管理中心做不了的事，或疑似被盗用的账号，请当天联系蜂巢的系统管理员。
